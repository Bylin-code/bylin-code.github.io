# Brady Y. Lin — Portfolio

Personal portfolio built with Jekyll and deployed from this repository.

## Local development

Requirements:

- Ruby 3.2.2 (the version used by Netlify)
- Bundler

Install the project dependencies once:

```sh
bundle install
```

Start the local development server:

```sh
bundle exec jekyll serve --livereload
```

### Project editor

With the local server running, open `http://localhost:4000/admin/`. The editor
loads every file in `content/_projects`, lets you select a reusable gallery
style and then 1–10 images, edit its fields and Markdown, preview YouTube
includes, and fill the selected number of image slots.

The gallery-style definitions live in `_data/project_templates.yml`; each one
is rendered by `_layouts/project.html` and works with 1–10 images. Slot order is
the order of the `gallery` items in project front matter. YouTube embeds use
`{% include youtube.html id="VIDEO_ID" %}`.

Every gallery style is flippable with `gallery_flip: true`. Split and Editorial
swap left/right columns; Hero swaps its lower text and supporting gallery;
Masonry moves its gallery above the text; Rows moves its text above the first
image row; and Filmstrip moves its lead image above the text.

The editor can save browser-local drafts, download project Markdown, and publish
projects, images, or Home/About/Resume edits to GitHub. Connect a token with
repository Contents read/write access using GitHub settings. The token stays in
session storage, not in the repository. Publishing creates a commit and triggers
the deployment workflow; it does not edit your local checkout. Pull afterward
before making further local changes. Page publishing reads the latest source and
preserves front matter fields that the editor does not expose.

Gallery cards can be dragged or moved with their arrow controls. Reordering a
card moves its image, crop, caption, and alt text together. Figure labels are
generated by the Jekyll layouts from gallery order, so caption fields contain
only caption text. Gallery images support custom-dimension crops; the separate
project thumbnail uses the fixed 4:3 ratio required by project cards. Cropped
and newly uploaded images remain local until published. Browser drafts omit
image data, so publish or download your work before closing the tab.

Open <http://127.0.0.1:4000>. Jekyll rebuilds after saved changes, and LiveReload refreshes the browser when supported.

To expose the preview to other devices on the same network:

```sh
bundle exec jekyll serve --livereload --host 0.0.0.0
```

## Production build

```sh
JEKYLL_ENV=production bundle exec jekyll build
```

The generated site is written to `_site/`, which is ignored by Git. Edit source
files, never generated output. GitHub Actions and Netlify both build from source.

## Content locations

- `content/pages/home.md`: homepage content
- `content/pages/`: standalone pages
- `content/_projects/`: portfolio projects
- `_data/menu.yml`: header and footer navigation
- `_data/social.json`: shared social/contact URLs; Contact page front matter selects ordering and labels
- `_includes/layout/`: page-shell sections such as the header and footer
- `_includes/navigation/`: menus, logo, and mobile navigation controls
- `_includes/components/`: reusable portfolio interface components
- `_includes/meta/`: metadata, fonts, analytics, and cookie integrations
- `_sass/base/`: typography, content, colors, and other global styles
- `_sass/layout/`: page-shell and grid styles
- `_sass/navigation/`: logo and menu styles
- `_sass/components/`: reusable portfolio component styles
- `_sass/pages/`: page-specific styles
- `_sass/vendor/`: third-party Bootstrap and Font Awesome source
- `_config.yml`: global site settings
- `assets/images/my-projects/<project-name>/`: project images

## Add a project

1. Create an image folder, such as `assets/images/my-projects/my-project/`.
2. Create `content/_projects/my-project.md`.
3. Add front matter using an existing project with the desired gallery arrangement as a reference.

Minimal example:

```yaml
---
layout: project
gallery_style: split
gallery_count: 1
gallery_flip: false
title: "My Project"
description: "A short description shown on project cards and the project page."
date: 2026-08-29
featured: false
display: true
role: "Engineer"
skills: "CAD, Embedded systems, Prototyping"
thumbnail: "/assets/images/my-projects/my-project/thumbnail.jpg"
gallery:
  - image: "/assets/images/my-projects/my-project/image-1.jpg"
    caption: "A useful description of the image"
---

Long-form project notes can go here in Markdown.
```

Project flags:

- `project_type: "Personal Project"` or `"Internship Project"` adds a visible tag to project cards and the project page. Set it with the Project tag dropdown in the editor.
- `collaboration: "Team"` or `"Solo"` adds a second tag after the project type. Set it with the Collaboration dropdown; leave it unspecified to hide this tag.

- `display: true` shows the project in the main project listing.
- `featured: true` also makes it eligible for the homepage's featured section.
- `date` controls date-based ordering.

All projects use `_layouts/project.html`. Choose `gallery_style` from `split`,
`rows`, `editorial`, `masonry`, `hero`, or `filmstrip`, with `gallery_count` from
1–10. Legacy numbered layouts have been removed; the editor still recognizes
older saved drafts. Caption numbering is generated automatically.

## Add a standalone page

Create `content/pages/page-name.md`:

```yaml
---
layout: basic
title: "Page Name"
permalink: "/page-name/"
---

Page content goes here.
```

Add it to `_data/menu.yml` only if it should appear in navigation.

## Troubleshooting

- `bundler: command not found: jekyll`: run `bundle install` first.
- Dependency errors after changing Ruby versions: run `bundle install` again with Ruby 3.2.2 active.
- A missing image: confirm the front-matter path matches the filename exactly, including capitalization.
- The canonical homepage is `content/pages/home.md`.


## Maintaining the editor and styles

- Page-specific styles live in `_sass/pages/`; shared section headings live in
  `_sass/components/_section-heading.scss`. Their imports stay at the end of
  `_sass/style.scss` to preserve the previous embedded-style cascade.
- `admin/shared.js` owns GitHub access, commit creation, Markdown helpers,
  image decoding/crop rendering, and page YAML updates. The two editor scripts
  own their respective UI state and crop controls.
- Project previews render the actual `_layouts/project.html` and project includes
  using LiquidJS. `_plugins/editor_templates.rb` exports those sources during
  every Jekyll build. The Gemfile explicitly loads this helper because the
  github-pages gem disables automatic local plugin discovery. Restart an already
  running Jekyll server after installing this change.
- The project layout is shared; editor Markdown/YouTube previews are approximate.
  Use the local public page to verify final Markdown and embedded media.
- `admin/vendor.js` is a checked-in browser bundle of YAML and LiquidJS. Normal
  Jekyll development and deployment require no Node build. To update the bundle:

```sh
npm ci
npm run build:admin
```

Dependencies and tests are excluded from the published site. To run editor tests:

```sh
npm test
npm run test:browser -- /tmp/site-after
```

For an appearance-preserving refactor, build a baseline before editing and a
second build afterward, then compare all public pages at mobile and desktop
sizes (including mobile navigation and hover states):

```sh
bundle exec jekyll build --destination /tmp/site-before
# Make source changes, then:
bundle exec jekyll build --destination /tmp/site-after
npx playwright install chromium
npm run test:visual -- /tmp/site-before /tmp/site-after
```

The comparison masks embedded PDFs/videos and blocks external requests so
third-party content cannot introduce unrelated screenshot differences. A small
perceptual tolerance ignores browser JPEG resampling noise; comparisons still
require zero changed pixels above that threshold. Set `VISUAL_FILTER` to a
route regular expression when rechecking a specific page.


## Homepage curation and card styling

The homepage uses `projects.order` in `content/pages/home.md` to choose the order
of featured work. A project must still have `featured: true` and `display: true`
to appear. Change that list to curate the selection without changing project dates.

`_data/project_cards.yml` holds short card summaries, separate from the longer
project-page description. Thumbnails use the original edge-to-edge, centered
4:3 crop without decorative frames. Original photographs are unchanged.

Typography and spacing live in the existing Sass components and page styles.
The homepage has the largest title; other pages share `--font-size-page-title`.
The palette uses warm off-white, deep purple, and one secondary background tone.

The Resume page lives at `/resume/`, with source in `content/pages/resume.md`.
The former `/experiences/` address redirects to `/resume/`.
